# CI는 GitHub Actions로 돌린다

- 상태: 확정 (2026-11-14). 무엇을 어떤 작업으로 돌릴지는 제안이다
- 관련: [테스트 개요](../testing/README.md), [정적 계열](../testing/static.md), [동적 계열](../testing/dynamic.md), [local-only.md](./local-only.md)

## 결정

정적 계열과 동적 계열의 검사를 **GitHub Actions에서 자동으로** 돌린다.

## 이유

- 저장소가 공개 저장소다. 공개 저장소는 GitHub이 제공하는 실행 환경을 무료로 쓸 수 있어서 하지 않을 이유가 없다.
- 손으로 돌리는 검사는 빠뜨리기 쉽다.
- 깨끗한 환경에서 처음부터 돌아가므로, 내 컴퓨터에서만 되는 상태를 걸러 낸다. 보고서가 요구하는 "읽은 사람이 재현할 수 있어야 한다"의 확인도 된다.

## localhost에서만 실행한다는 결정과의 관계

[local-only.md](./local-only.md)는 서비스를 배포하지 않는다는 결정이다. CI는 테스트를 돌리는 임시 환경이고 서비스를 띄워 두는 곳이 아니므로 그 결정과 어긋나지 않는다.

## 작업 구성 (제안)

| 작업 | 돌리는 것 | MySQL |
|---|---|---|
| 정적 | 서버 컴파일·형식·구조 규칙, SQL 형식, 웹 타입·린트, Firebase 잔존 검사, 문서 링크 | 필요 없음 |
| 동적 | 스키마, 권한, 단위, 통합, 동시성, 계약 테스트 | 필요 |

- 정적 작업이 먼저 끝나고 빨리 실패하게 한다.
- 동적 작업의 MySQL은 CI 안에서 컨테이너로 띄운다. GitHub의 Linux 실행 환경에는 Docker가 들어 있다. 이미지는 로컬과 같은 `mysql:8.4`이고, 테스트가 직접 띄운다([mysql-docker.md](./mysql-docker.md)).
- 워크플로 파일은 [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)이다(2026-11-18). 아래 미정 항목은 제안대로 썼다: 모든 푸시와 풀 리퀘스트에서 돌리고, 문서만 바뀐 푸시도 건너뛰지 않는다. **GitHub에서 돌려 보지 않았다.** 푸시한 뒤에 확인해야 한다.
- 지금 정적 작업이 하는 것은 컴파일 검사뿐이다. 형식, 구조 규칙, SQL 형식, 문서 링크 검사는 도구를 정하지 않아서 들어 있지 않다. 웹이 없어서 웹 검사도 없다.
- 브라우저 테스트는 넣지 않는다. 자동화할지가 미정이다([동적 계열](../testing/dynamic.md)).
- 성능 측정은 넣지 않는다. 통과와 실패가 없고, CI 환경의 수치는 보고서에 쓸 수 없다.

## 지켜야 할 것

- **공개 저장소이므로 워크플로와 설정 파일에 실제 비밀 값을 넣지 않는다.** 테스트용 DB 계정의 비밀번호는 테스트에만 쓰는 값으로 두고, 다른 곳에 쓰는 비밀번호를 재사용하지 않는다.
- 시드 데이터에는 만들어 낸 개인정보만 쓴다([project-positioning.md](./project-positioning.md)). CI 로그도 공개된다.

## 미정

- 언제 돌릴지. 제안은 모든 푸시에서 돌리는 것이다. 지금 작업 방식은 브랜치에서 커밋하고 로컬에서 main으로 병합하므로 풀 리퀘스트가 없다.
- 문서만 바뀐 푸시에서 서버·웹 검사를 건너뛸지.
- CI가 실패한 채로 main에 병합되는 것을 막을지.
