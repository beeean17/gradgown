# 과제용 구현이고 실제 운영에는 쓰지 않는다

- 상태: 확정 (2026-11-13)
- 관련: [topic.md](./topic.md), [scope.md](./scope.md), [local-only.md](./local-only.md)

## 결정

gradgown은 **텀 프로젝트 제출용**이다. 실제 운영에는 쓰지 않는다. 운영용 이전은 grad42 쪽에서 더 보강해서 따로 진행한다.

기준은 "보고서를 쓸 수 있을 정도"다.

## 맥락: grad42에 이미 있는 이전 작업

grad42 저장소의 `feat/spring-migration` 브랜치에 Spring Boot + **PostgreSQL** 이전 작업이 있다(2026-11-13 확인).

| 항목 | 내용 |
|---|---|
| 규모 | 커밋 210개, 마지막 커밋 2026-10-04 |
| 진행 | 계정·인증과 공지 API는 구현, 예약은 스키마와 엔티티 단계 |
| 수준 | 운영 수준 설계. 필드 암호화, 속도 제한, Turnstile, 메일 인증을 포함한다 |
| 범위 차이 | St:talk 멘토링을 기본 범위에서 뺐고, 예약 규칙은 Flutter 3.1.0 시절 기준이다 |
| 문서 | `docs/migration/01~09` |

gradgown은 이 브랜치를 대체하지 않는다. 설계를 참고할 뿐이다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| 기존 브랜치를 그대로 제출 | DB가 PostgreSQL이다. 인증·보안 비중이 커서 6쪽 보고서에서 DB 내용이 묻힌다 |
| 기존 브랜치를 MySQL로 전환해 운영용과 과제를 합침 | PostgreSQL 전용 제약·잠금·네이티브 SQL을 다시 써야 해서 비용이 가장 크다 |

## 영향

- 운영 수준의 보안 요소(필드 암호화, 속도 제한, 봇 차단, 메일 발송)는 만들지 않는다.
- 기존 Firestore 데이터를 가져오지 않는다. 시드 데이터로 시작한다.

## 지켜야 할 것

- 암호화가 없으므로 **실제 학생 개인정보를 넣지 않는다.** 시드 데이터와 보고서 화면에는 만들어 낸 이름·학번·연락처만 쓴다.
