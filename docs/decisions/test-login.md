# Google 로그인 대신 테스트 계정으로 로그인한다

- 상태: 확정 (2026-11-13). 구체적인 방식은 미정
- 관련: [scope.md](./scope.md), [project-positioning.md](./project-positioning.md), [data-model.md](./data-model.md)

## 결정

원본 서비스는 Firebase Auth의 Google 로그인을 쓴다. 이 프로젝트는 그것을 옮기지 않고 **미리 만들어 둔 테스트 계정으로 로그인**한다.

## 이유

- 보고서를 쓸 수 있을 정도면 된다. 인증은 이 과제의 주제가 아니다.
- Google OAuth 설정과 Firebase Auth 의존을 통째로 뺄 수 있다.

## 영향

- 사용자 등급(학생, 관리자, 마스터)은 데이터 모델에 그대로 둔다. 원본의 권한 구분이 등급에 달려 있기 때문이다.

| 등급 | 원본에서 할 수 있는 것 |
|---|---|
| 학생 | 공개 문서 읽기, 본인 예약·신청 읽기와 변경 |
| 관리자 | 관리자 앱 조회와 명단 내보내기 |
| 마스터 | 관리자 앱의 모든 작업 |

- 등급은 어느 서버에 로그인할 수 있는지와 어느 DB 계정으로 접속하는지도 정한다. 학생은 학생용 서버에, 관리자와 마스터는 관리자용 서버에 로그인한다([admin-server-split.md](./admin-server-split.md), [db-privileges.md](./db-privileges.md)).
- 실제 로그인이 없으므로 보고서의 한계로 적는다.

## 미정

- 로그인 방식. 제안은 시드 데이터에 등급별 계정을 넣어 두고 로그인 화면에서 계정을 고르는 것이다.
- 서버가 등급별 권한을 어디까지 검사할지
