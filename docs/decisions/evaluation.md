# 평가는 DB 수준 비교를 중심으로 한다

- 상태: 제안 (2026-11-13). 아직 확정하지 않았다
- 관련: [topic.md](./topic.md), [local-only.md](./local-only.md), [data-model.md](./data-model.md), [과제 요구사항](../requirements/course-requirements.md)

## 제안

보고서의 Evaluation은 **"MySQL이 Firestore보다 빠르다"가 아니라, 구조가 바뀌어서 무엇이 달라졌는지**를 보인다. 중심은 DB 수준의 비교이고, 프론트 로딩 수치는 배경으로만 쓴다.

## 이유

- 주제의 동기 중 하나가 성능 개선이다([topic.md](./topic.md)). 보고서 양식도 결과와 그 이유를 쓰라고 요구한다.
- Firestore의 단일 문서 읽기는 그 자체로 느리지 않다. 엔진끼리의 속도 비교는 근거를 대기 어렵다.
- localhost에서만 실행하므로([local-only.md](./local-only.md)) 운영 중인 Firebase 사이트와 같은 조건으로 응답 시간을 잴 수 없다.
- 데이터베이스 과목의 보고서다.

## 평가 항목 후보

### 1. 조회 구조

grad42 `feat/spring-migration` 브랜치의 `docs/migration/04-api.md`가 현행 관리자 API의 비효율을 A1~A8로 정리해 두었다. 그중 DB 구조에서 오는 것이 후보다.

| 항목 | Firebase 버전 | MySQL 버전에서 보일 것 |
|---|---|---|
| A1 예약 명단 검색 | 예약 51건을 읽어 50건을 보여 주고, 이름·학번·전화·상태 필터를 그 페이지 안에서만 적용한다 | `WHERE`, 인덱스, 페이지네이션. 첫 페이지 밖의 일치 항목도 찾는다 |
| A4 공지·FAQ | 각각 문서 하나의 map이다. 숨김 항목도 공개로 읽히고, 저장할 때 문서 전체를 다시 쓴다 | 행 단위 조회와 갱신. 노출 조건을 `WHERE`로 적용한다 |
| A5 감사 로그 | 최근 200건을 읽어 브라우저에서 검색한다 | 서버 필터와 페이지네이션 |
| St:talk 신청 현황 | 행사의 신청을 모두 읽어 브라우저에서 선택지 × 차시 인원을 센다 | `GROUP BY` 한 번 |

잴 수 있는 지표는 읽는 문서 수 대 반환 행 수, 요청 왕복 횟수, 응답 크기, `EXPLAIN` 실행 계획이다.

### 2. 정합성

규칙을 코드가 아니라 스키마가 보장한다는 것을 보인다([data-model.md](./data-model.md) "코드에서 DB 제약으로 옮기는 규칙").

- 같은 회차에 두 번째 예약을 넣으면 UNIQUE 위반으로 거부되는 것
- 두 차시에 같은 선택지를 넣으면 `CHECK` 위반으로 거부되는 것
- 같은 `operation_id`로 두 번 요청하면 한 번만 처리되는 것
- 동시에 같은 예약을 고치면 한쪽이 `version` 충돌로 거부되는 것

### 3. 프론트 로딩 (배경)

grad42 `docs/perf/2026-11-04-baseline.md`의 운영 측정값을 Background에서 인용한다.

- 모바일 Lighthouse 기준 홈 LCP는 10.85초였고, 프론트 개선 후 8.68초다.
- 첫 화면 내용이 "JS 1.4MB 실행 → reCAPTCHA 로드 → App Check 토큰 → Firestore 응답"을 차례로 기다린다.
- Firestore SDK가 번들의 24.9%, reCAPTCHA가 356KB다.

이전하면 Firestore SDK와 App Check가 빠지고 REST 호출로 바뀐다. 다만 로컬 실행으로는 이 효과의 절대값을 운영과 비교할 수 없다. 번들 크기와 첫 화면 요청 수처럼 실행 환경과 무관한 것만 전후로 비교한다.

## 한계로 적을 것

보고서 양식은 단점과 안정성도 쓰라고 요구한다.

- Firestore의 실시간 구독(`onSnapshot`)이 없어진다. 관리자가 접수를 닫아도 열려 있는 화면에 바로 반영되지 않는다.
- Firebase가 대신 해 주던 인증, 보안 규칙, 호스팅을 직접 맡아야 한다. 이 프로젝트는 그 부분을 테스트 로그인과 로컬 실행으로 생략했다.
- 측정은 로컬 환경의 합성 데이터로 한다.
