# MySQL은 Docker 컨테이너로 띄운다

- 상태: 확정 (2026-11-14). 구성의 세부는 제안이다
- 관련: [local-only.md](./local-only.md), [ci.md](./ci.md), [db-privileges.md](./db-privileges.md), [동적 계열](../testing/dynamic.md)

## 결정

MySQL을 **Docker 컨테이너로** 띄운다. 개발, 테스트, CI에서 모두 같다. macOS에 MySQL을 직접 설치하지 않는다.

## "어떻게 띄울지"의 뜻

어디서 실행할지는 이미 정해져 있었다. 개발 중에는 개발 머신([local-only.md](./local-only.md)), CI에서는 GitHub의 실행 환경이다([ci.md](./ci.md)). 이 결정은 그 안에서 MySQL 프로세스를 어떤 방식으로 실행할지를 정한 것이다.

## 이유

- **CI와 같은 환경이다.** GitHub Actions도 MySQL을 컨테이너로 띄운다. 로컬과 CI가 같은 이미지, 같은 버전을 쓴다.
- **재현할 수 있다.** 명령 하나로 빈 DB에서 테이블, 계정 셋, `GRANT`, 시드 데이터까지 올라온다. 보고서가 요구하는 "읽은 사람이 재현할 수 있어야 한다"에 맞는다.
- **테스트용 DB를 분리하기 쉽다.** 테스트가 임시 컨테이너를 띄웠다가 지우면 개발용 데이터와 섞이지 않는다.

## 검토한 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| macOS에 직접 설치(Homebrew 등) | 버전과 설정이 개발 머신에만 있어 CI와 어긋날 수 있다. 계정 셋과 초기화를 손으로 해야 한다 |
| 슬라이드의 방법(소스 빌드, APT, Windows 설치 프로그램) | Linux와 Windows 기준이다. 재현성 면에서 직접 설치와 같은 문제가 있다 |

## 구성 (제안)

| 용도 | 방식 |
|---|---|
| 개발 | Compose 파일 하나로 MySQL을 띄운다. 처음 뜰 때 초기화 스크립트가 테이블, 뷰, 계정 셋, `GRANT`, 시드 데이터를 만든다 |
| 테스트 | 테스트가 임시 컨테이너를 직접 띄운다(Testcontainers). 개발용 DB와 따로다 |
| CI | 테스트와 같은 방식이다. GitHub의 Linux 실행 환경에 Docker가 들어 있다 |

서버와 웹은 컨테이너에 넣지 않고 개발 머신에서 직접 실행하는 것을 제안한다. 컨테이너에 넣으면 고칠 때마다 다시 빌드해야 한다.

## 영향

- 개발과 테스트를 하려면 Docker Desktop이 켜져 있어야 한다.
- 초기화 스크립트가 스키마의 기준이 된다. DDL, `GRANT`, 시드 데이터가 저장소에 SQL 파일로 들어간다.
- 계정 셋의 비밀번호가 설정 파일에 들어간다. 테스트 전용 값만 쓴다([ci.md](./ci.md)).

## 미정

- MySQL 이미지의 버전. 8.x 안에서 하나로 고정한다. 제안은 장기 지원 버전인 8.4다. 슬라이드는 8.0.31을 썼다.
- 테스트 사이에 DB 상태를 되돌리는 방법([동적 계열](../testing/dynamic.md)).
- 스키마 변경을 관리하는 방법. 초기화 스크립트만 둘지, 마이그레이션 도구를 쓸지([tech-stack.md](./tech-stack.md)).
- 개발용 DB의 데이터를 컨테이너를 지워도 남길지.
