# 보고서 요구사항과 충족 현황

> 2026-11-14 작성. 요구사항의 근거는 과제 안내 슬라이드다([course-requirements.md](./course-requirements.md)). 충족 현황은 이 저장소의 문서와 구현 상태를 기준으로 한다.

보고서는 아직 쓰지 않았다. 그래서 이 문서는 **"보고서의 각 항목을 쓸 재료가 준비됐는가"**를 본다.

## 판정 기준

| 판정 | 뜻 |
|---|---|
| 준비됨 | 쓸 내용이 문서에 있다. 글로 옮기기만 하면 된다 |
| 일부 | 내용의 일부만 있다. 무엇이 빠졌는지 적었다 |
| 구현 필요 | 무엇을 쓸지는 정했지만 코드나 실행 결과가 있어야 쓸 수 있다 |
| 없음 | 아직 아무것도 없다 |
| 확인 필요 | 과제 쪽에 확인해야 판단할 수 있다 |

강도는 세 가지다. **필수**는 슬라이드가 요구한 것, **권장**은 슬라이드가 권한 것, **관찰**은 예시 보고서에서 본 것이다.

## 요약

| 판정 | 항목 수 | 항목 |
|---|---|---|
| 준비됨 | 6 | RPT-21, 23, 31, 41, 47, 54 |
| 일부 | 9 | RPT-3, 10, 20, 22, 25, 30, 40, 43, 70 |
| 구현 필요 | 8 | RPT-24, 44, 45, 46, 50, 51, 52, 53 |
| 없음 | 4 | RPT-2, 26, 42, 60 |
| 확인 필요 | 1 | RPT-1 |

설계의 근거와 한계는 준비됐다. 빠진 것은 세 부류다.

1. **구현과 실행 결과.** 코드가 없어서 DB 연결, DB 연동 코드, 실행 결과, 수치를 쓸 수 없다.
2. **그림.** ER 다이어그램과 전체 구조 그림이 없다. ER 모델은 슬라이드가 보고서 구성 예시와 General Advice에서 거듭 요구하고, 예시 보고서 세 개가 모두 실은 항목이다.
3. **글의 뼈대.** 보고서 개요, 참고 문헌, Contribution 문장이 없다.

| RPT-3 | 프로젝트, DB 스키마, DB와 상호작용하는 코드를 설명한다 | 필수 | 1번 4쪽 | 일부 | 프로젝트 설명은 있다([topic.md](../decisions/topic.md), [scope.md](../decisions/scope.md)). 스키마는 초안이다. 코드는 없다 |

## Introduction

|---|---|---|---|---|---|
| RPT-20 | 주제가 왜 중요한지 | 필수 | 1번 5~6쪽 | 일부 | 개인적인 동기(내년 운영, 성능)는 있다([topic.md](../decisions/topic.md)). 읽는 사람에게 왜 중요한지, 즉 소규모 서비스가 Firebase로 시작했다가 관계형 DB로 옮기는 일반적인 맥락은 정리하지 않았다 |
| RPT-21 | 문제를 정의한다 | 필수 | 1번 5~6쪽 | 준비됨 | 조회 구조의 비효율(A1, A4, A5), 규칙이 코드에만 있는 점, 첫 화면 로딩 사슬([evaluation.md](../decisions/evaluation.md), [data-model.md](../decisions/data-model.md)) |
| RPT-22 | 기존 연구나 방식과 비교한다 | 필수 | 1번 5~6쪽 | 일부 | 기존 방식은 Firebase 버전이다. 인용할 문헌이 하나도 없다. 예시 3은 직접 다룬 연구가 없다고 밝히고 비슷한 시스템을 참고했다고 썼다 |

## 지금 할 수 있는 것

구현을 기다리지 않아도 되는 항목이다.

| 할 일 | 해결되는 항목 |
|---|---|
| 강의 공지에서 분량, 언어, 제출 형식 확인 | RPT-1, RPT-2 |
| 보고서 개요 작성(섹션별로 무엇을 쓸지, 어느 서비스를 자세히 쓸지) | RPT-2, RPT-26 |
| ER 다이어그램 그리기 | RPT-42 |
| 전체 구조 그림 그리기 | RPT-40 |
| 현재 Firebase 구조를 한 문서로 정리하고 화면 자료 모으기 | RPT-30 |
| 참고 문헌 찾기(NoSQL에서 관계형으로의 이전, Firestore와 MySQL 문서) | RPT-22 |
| 주제의 일반적인 중요성 정리 | RPT-20 |
