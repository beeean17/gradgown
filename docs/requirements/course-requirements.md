# 과제 요구사항

> 2026-11-13 분석. 근거는 [course-materials/](../course-materials/)의 슬라이드 4개다. 슬라이드에 없는 내용은 맨 아래 "슬라이드에 없는 것"에 따로 적었다.

과제는 **DB를 활용하는 서비스를 구현하고 6쪽 보고서로 설명하는 텀 프로젝트**다. 채점 무게는 구현 스택이 아니라 ER 모델, DB 연동 코드, 실행 결과, 회고에 있다.

## 슬라이드별 역할

| 문서 | 내용 | 프로젝트 관련성 |
|---|---|---|
| 1. Project Introduction | 퀴즈 안내, 텀 프로젝트 정의, 보고서 작성법, MySQL 설치와 JDBC 연결 | 핵심 요구사항 |
| 2. Project Introduction2 | SQLite 소개, C 연동(gcc, Visual Studio), DB Browser | 환경 설정 참고 |
| 3. Executing SQL | MySQL Workbench에서 테이블 생성, `ALL` 집합 비교 쿼리 실행 | 퀴즈용에 가깝다 |
| 4. Project Examples | 예시 보고서 3개와 General Advice | 기대 수준의 기준 |

퀴즈는 텀 프로젝트와 별개다. 간단한 SQL 문제를 설치한 DB에서 확인하고 2쪽으로 설명한다.

## 구현 요구사항

| 항목 | 요구 | 근거 |
|---|---|---|
| 주제 | 자유. PoS, 수강신청, 고객 서비스 등이 예시다. 실제 문제를 고르라고 권장한다 | 1번 3쪽, 4번 23쪽 |
| 형태 | CLI 또는 GUI 프로그램 | 1번 3쪽 |
| DB | MySQL, SQLite가 예시다 | 1번 3쪽 |
| 언어 | 제한 없음. C, Java, Python이 예시다 | 1번 3쪽 |
| 스택의 비중 | "I do not care about Programming model or DB" | 4번 23쪽 |

보고서에 반드시 들어가야 하는 것은 다음 네 가지다(4번 23쪽 General Advice).

- ER 모델
- DB와 상호작용하는 코드
- 실행 결과
- 프로젝트에서 얻은 발견과 더 잘할 수 있었던 점

## 보고서 요구사항

분량은 6쪽이다. 프로젝트, DB 스키마, DB와 상호작용하는 코드를 설명한다(1번 4쪽).

| 섹션 | 써야 하는 것 |
|---|---|
| Abstract | 작업을 5~6문장으로 설명 |
| Introduction | 주제의 중요성 → 문제 정의 → 기존 방식과 비교 → 제안 내용 → 평가 → 논문 구성 순서. Contribution을 최소 3개(분석, 설계·구현, 평가) 적는다 |
| Background and Motivation | 대상 시스템이 무엇인지 |
| Design and Implementation | 전체 아키텍처(목표, 설계 방향) → 세부 설계(ER 모델, 스키마) → 구현(DB 연결, 실제 함수). 읽은 사람이 재현할 수 있어야 한다. 단점과 안정성·견고성도 적는다 |
| Evaluation | 결과와 그 이유, 결과 분석, 기존 방식과 비교 |
| Conclusion | — |

작성 가이드는 시스템 논문 양식을 빌려온 것이라 성능 향상과 state-of-the-art 비교 항목이 있다. 같은 슬라이드의 "Example Report"는 DB 프로젝트에 맞춰 이를 줄여서 보여 준다. Design에는 데이터 구조 설계, E-R 모델, DB 연결을 쓰고 Evaluation에는 쿼리 실행 결과를 쓴다(1번 14쪽).

## 예시 보고서의 수준

| 예시 | 스택 | 규모 | 눈에 띄는 점 |
|---|---|---|---|
| 수강 장바구니 | MySQL, Java | ER 모델의 엔티티 4개, CLI 메뉴 3개(담기, 조회, 삭제) | 입력 검증, 중복 방지. 한계를 스스로 적었다 |
| 항공 예약 | Python | 릴레이션 10개, 고객·항공사 역할별 메뉴 | 서브쿼리. 기능 영역 두 개만 골라 자세히 설명했다 |
| 비교과 신청 | MySQL, Python | 테이블 7개 | 뷰, 사용자별 권한(GRANT). 실제 학교 사이트의 불편을 개선했다 |

## 슬라이드에 없는 것

다음은 네 슬라이드 어디에도 없다. 강의 공지에서 확인해야 한다.

- 제출 기한
- 배점과 채점 기준
- 개인 과제인지 팀 과제인지
- 제출 형식(코드를 함께 내는지, 보고서만 내는지)
- 보고서 언어. 예시 보고서 세 개는 모두 영어다
- 발표나 시연이 있는지
- 6쪽이 상한인지 정확한 분량인지
