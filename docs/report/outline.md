## 보고서가 하려는 말

한 문장으로 줄이면 이렇다.

> 운영 중인 Firebase 서비스를 MySQL로 옮기면서, **코드가 검사하던 규칙을 스키마의 제약으로, 등급별 접근 제어를 DB 계정의 권한으로, 브라우저가 하던 검색과 집계를 SQL로** 옮겼고, 각각이 실제로 동작하는 것을 테스트와 측정으로 보였다.

하지 않는 말도 정해 둔다. [evaluation.md](../decisions/evaluation.md)의 검증에서 틀렸던 주장들이다.

- "MySQL이 Firestore보다 빠르다"고 하지 않는다. 시간은 비교하지 않았다.
- "원본이 틀린 값을 보인다"고 하지 않는다. 원본은 상한을 화면에 밝히고, 넘으면 오류를 낸다.
- "MySQL이 덜 읽는다"고 하지 않는다. 줄어든 것은 내려오는 양과 왕복 횟수다.
- 이전의 효과가 아닌 것(grad42가 스스로 한 개선)을 이전의 효과로 세지 않는다.

### Contribution (RPT-25)

슬라이드는 분석, 설계와 구현, 평가의 세 가지 이상을 요구한다.

1. **분석.** 운영 중인 서비스가 Firestore에 닿는 지점을 모두 찾고, 코드(Cloud Functions, 브라우저)가 지키던 규칙을 하나씩 뽑아 "스키마가 지킬 수 있는 것"과 "서버 코드에 남아야 하는 것"으로 나눴다.
2. **설계와 구현.** 테이블 11개의 스키마. 유효 예약 하나, 슬롯과 회차의 일치, 차시 선택 규칙을 생성 컬럼의 UNIQUE, 복합 FK, `CHECK`로 표현했다. 학생·관리자·마스터의 세 DB 계정과 뷰로 등급 간 경계를 DB가 지키게 했고, 관리자용 서버는 로그인한 사람의 등급으로 DB 계정을 고른다. 원본의 두 웹을 가져와 데이터 계층만 바꿔 끝까지 동작하게 했다.
3. **평가.** 제약과 권한이 거부해야 할 것을 거부하는지를 실제 MySQL에서 테스트 257개로 확인했다. 같은 합성 데이터를 MySQL과 Firestore 에뮬레이터에 넣고 원본의 쿼리와 이 프로젝트의 SQL이 읽는 양을 비교했고, 측정이 알려 준 대로 인덱스를 더했다.
4. **한계의 정리.** 이전으로 잃은 것(실시간 구독, 사용자 단위의 읽기 규칙)과 측정이 말해 주지 않는 것을 적었다. 측정의 해석을 독립적으로 검증해 틀린 주장 셋을 고친 경위도 함께 적는다.

### 5. Conclusion and Lessons Learned (0.4쪽)

- 결론 세 문장: 무엇을 옮겼고, 무엇이 확인됐고, 무엇을 잃었나.
- 얻은 것 (RPT-70). 아래에서 서넛을 고른다.
  - 스키마가 지키는 규칙에서는 결함이 나오지 않았고, 결함은 서버가 입력을 받는 경계에서 나왔다.
  - 초기화 스크립트의 시간대 문제를 "같은 시작 시각의 슬롯 둘" 테스트가 잡았다. 통과해야 할 것이 아니라 거부돼야 할 것이 통과해서 드러났다.
  - 실시간 구독을 없애자 "언제 다시 읽을지"가 웹의 일이 됐고, 그 판단이 빠진 곳마다 화면이 낡은 값을 보였다.
  - 측정을 직접 설계한 쪽의 해석은 유리한 쪽으로 기울었다. 독립된 검증이 틀린 주장 셋을 찾았다.
  - MySQL 권한은 행 단위가 아니라서, Firestore Rules가 해 주던 "본인 것만 읽는다"는 서버 코드로 넘어왔다.
- 더 잘할 수 있었던 것: **아직 정리하지 않았다.** 후보는 검색 조건(`LIKE '%…%'`)이 인덱스를 못 쓰는 것, 신청 현황 화면이 명단 전체를 받는 것, 접수를 닫는 순간의 경쟁.

## 문제와 해결의 대응

예시 보고서 3이 한 방식이다. 2절에서 문제를 정의하고, 3절이 해결을, 4절이 증거를 같은 번호로 받는다.

| | 문제 (2절) | 해결 (3절) | 증거 (4절) |
|---|---|---|---|
| P1 | 검색과 집계를 브라우저가 한다. 받은 페이지 밖은 찾을 수 없고, 상한을 넘으면 볼 수 없다 | `WHERE`, 키 기반 페이지 나누기, `GROUP BY` | 표 5, 표 6 |
| P2 | 규칙이 함수 코드에만 있다. 코드가 틀리면 어긋난 데이터가 들어간다 | UNIQUE, 복합 FK, `CHECK`, PK | 스키마 테스트 42개, 동시성 테스트 |
| P3 | 숨긴 공지가 누구에게나 내려간다. 등급별 권한이 함수 코드의 표에 있다 | DB 계정 셋, 뷰, 컬럼 단위 권한 | 권한 테스트 124개, 관리자의 쓰기를 MySQL이 거부한 로그 |
| P4 | 첫 화면이 reCAPTCHA, App Check, Firestore 응답을 차례로 기다린다 | REST와 같은 출처의 요청 | 번들 크기, 첫 화면 요청 |
